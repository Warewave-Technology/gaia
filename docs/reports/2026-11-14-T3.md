## Mimara özet

- T3 tamam. Gate `PASS`, ama sadece Kopia tuning'iyle. Kopia'nın varsayılan splitter'ı (`DYNAMIC-4M-BUZHASH`) ile hız gate'i tutmadı: `zstd` 2.77×, `none` 2.65×.
- Üç çalıştırmada tamamlanan 10 run'ın hepsinde iki restore (full + incremental) sha256 ile byte-identical çıktı.
- **Gate'i geçen ayar:**
  - `s2-default/FIXED-4M` iki ölçümde de geçti: 1.66× ve 1.82×. İkinci ölçüm, bütün çalıştırmaların en düşük baseline'ına göre de geçiyor (1.86×).
  - `zstd-fastest/FIXED-4M` önce 1.96× ile geçti, ikinci ölçümde 2.10× ile kaldı. Güvenilir değil.
  - Doğrulama tekrarında baseline dar bir aralıkta kaldı: 18.511–18.908 s. Önceki 18.097–32.553 s'lik oynama muhtemelen dolan diskten.
- **Sayıyı ne değiştirdi:**
  - Splitter `FIXED-4M` (none: 59.272 → 44.586 s).
  - Hızlı compression; `FIXED-4M` ile none 44.586, `zstd-fastest` 43.184, `s2-default` 37.785 s.
  - `--parallel=8` aynı çalıştırmada hiçbir şeyi değiştirmedi: 44.172 / 44.586 s, 4 vCPU.
  - CPU %53–76 busy; kaynak ve repo aynı sanal diskte.
- **ONAY GEREKİYOR, gate tanımı:** `qemu-img convert` baseline'ı büyük ihtimalle image'ın sadece dolu 14.7 GiB'ını okuyor (çıkarım). Kopia ise 30 GiB'ın tamamını okuyor. Konfigürasyon başına hâlâ en fazla 2 ölçüm var.
- **ONAY GEREKİYOR, varsayılan ayar:** Gaia disk image repo'ları için `s2-default` + `FIXED-4M` öneriyorum. Splitter repo oluşturulurken sabitleniyor.
  - Alternatif `s2-default` + `FIXED-1M` da gate'i geçti (1.86×). Incremental'da 2.88 kat daha az yer kaplıyor.
  - Ama incremental restore'u 1.79× yavaş (385 / 215 s).
- **Incremental:** CBT yok; Kopia her snapshot'ta image'ın tamamını okuyor (21–59 s). Dağınık %1 değişiklik repo'yu değişen verinin 5–47 katı büyüttü. Bu, chunk boyutuyla birebir açıklanıyor: 3630 × 4 MiB beklenen, 15.26 GB ölçülen.
- **Restore** backup'tan 3–5× yavaş: full restore 133–207 s. Gate'te yok ama RTO açısından önemli; nedeni ölçülmedi.
- **Harness hatası:** Kopia cache'i work dir silinince `~/.cache/kopia` altında kalıyordu ve Çalıştırma 2'de diski doldurdu.
  - Düzeltildi; Docker'da ve lab'da doğrulandı.
  - 4 run sonra cache 104M, disk başlangıçtaki 17G'ye döndü.
  - fstrim 139 GiB geri verdi.
- **Taslak düzeltmeleri:**
  - imgtool `mutate` nondeterministikti. Düzeltmeden sonra repo boyutları çalıştırmalar arasında tekrarlanıyor.
  - make-test-image seed'leri tekrar ediyordu, bu da dedup'u şişiriyordu.
  - run.sh restore başarısız olunca JSON yazamıyordu.

### Kopia CLI flag doğrulaması

`t3-kopia.sh`, run.sh'ın kullandığı her flag'i kurulu Kopia'nın `--help` çıktısında arıyor. Bu çıktı Çalıştırma 2'den; Çalıştırma 1'deki aynı:

```text
0.23.1 build: 72ec08fd8edb86c67ed27099bf1b955e1f308ffa from: kopia/kopia
kopia repository create filesystem --path=PATH                Path to the repository
kopia repository create filesystem --object-splitter=DYNAMIC-4M-BUZHASH
kopia policy set --compression=COMPRESSION  Compression algorithm
kopia policy set --[no-]global              Select the global policy.
kopia snapshot list --[no-]json                Output result in JSON format to stdout
kopia repository status --[no-]json             Output result in JSON format to stdout
usage: kopia restore [<flags>] <sources>...
```

Taslaktaki flag'lerin hepsi 0.23.1'de doğru, değiştirilmedi:
- `repository create filesystem --path`
- `policy set --global --compression`
- `snapshot list --json` (`.[-1].id`)
- `restore`

Yeni eklenen `--cache-directory` (`8d33258`) Docker'da 0.23.1 arm64 paketinin `--help` çıktısına karşı doğrulandı. Lab'daki flag kontrolü listesine de eklendi:

```text
kopia repository create filesystem --cache-directory=PATH     Cache directory ($KOPIA_CACHE_DIRECTORY)
```

  - `s2-default` hem en hızlısı hem repo'yu 0.305'e küçültüyor.

**4. Incremental büyüme chunk boyutuyla açıklanıyor.**
- `imgtool mutate` 491520 adet 64 KiB'lık bloktan 4915'ini rastgele değiştiriyor.
